# Prapti architecture

Prapti is a mobile-first web app that helps low-income students in Telangana find
government scholarships they are likely eligible for. It is free, has no accounts,
no database and no paid services. The server is plain Node 18+ with zero npm
dependencies.

## Folder layout

```
prapti/
  package.json          scripts: start, build, test, accuracy
  server.js             node:http server, routing, static files, sessions, API stubs
  build.js              copies public/ to dist/, fingerprints assets, writes sw.js precache
  ARCHITECTURE.md       this file
  .gitignore            dist/, node_modules/
  public/               source assets (served directly in development)
    index.html          app shell
    css/                stylesheets
    js/
      app.js            router and route registry
      i18n.js           t(key), setLang(code)
      pages/            one module per page (render(container, params))
    locales/
      en.json
      te.json
      hi.json
    sw.js               service worker (contains __PRECACHE_LIST__ and __CACHE_VERSION__)
    manifest.webmanifest
  dist/                 generated by `npm run build`; never edited by hand
  tests/                node:test files, run by `npm test`
```

## Routing

The server returns the same app shell HTML for every page route. The browser then
renders the right page with the History API.

| Path            | Server response        | Client page module              |
|-----------------|------------------------|---------------------------------|
| `/`             | app shell              | `pages/home.js`                 |
| `/results`      | app shell              | `pages/results.js`              |
| `/scheme/:id`   | app shell              | `pages/scheme.js` (id param)    |
| `/mee-seva`     | app shell              | `pages/mee-seva.js`             |
| `/tracker`      | app shell              | `pages/tracker.js`              |
| `/about`        | app shell              | `pages/about.js`                |
| `/rules-check`  | app shell              | `pages/rules-check.js`          |
| `/helper`       | app shell              | `pages/helper.js`               |
| `/editor`       | app shell              | `pages/editor.js`               |
| `/demo`         | app shell              | `pages/demo.js`                 |

- The shell is `dist/index.html` when `dist/` exists, otherwise `public/index.html`.
- Any other path that is not a static file and not under `/api/` returns 404.
- Static files come from `dist/` when it exists, otherwise from `public/`. Any path
  that decodes to contain `..`, a backslash or a NUL byte is rejected with 400.

### Client-side routing

`public/js/app.js` holds the route registry. It maps each path pattern to a page
module. On load and on every `popstate` or intra-app link click, it matches
`location.pathname`, imports the module, and calls `render(container, params)`.
Links use `history.pushState`. Unknown paths show the Home page's not-found message.

## Caching and fingerprinting

- `build.js` produces fingerprinted names such as `css/app.1a2b3c4d.css`. The
  hash is the first 8 hex characters of the SHA-256 of the file content.
- Fingerprinted assets are served with `Cache-Control: public, max-age=31536000, immutable`.
- HTML and `sw.js` are served with `Cache-Control: no-cache`.
- `dist/manifest.json` maps logical paths (for example `css/app.css`) to
  fingerprinted paths. The server reads it for information only.

## i18n

- Locale files are `public/locales/en.json`, `te.json` and `hi.json`. They are flat
  objects of key to string.
- `public/js/i18n.js` exports:
  - `t(key)`: returns the string for the current language, falling back to English,
    then to the key itself.
  - `setLang(code)`: sets the current language to `en`, `te` or `hi`, saves it to
    `localStorage` under `prapti.lang`, updates `<html lang="...">`, and re-renders
    the current page.
- The initial language is the saved choice, otherwise `en`.

## State

- **Server:** nothing is stored on the server except an in-memory session map,
  and the editor session. Nothing is written to disk.
- **Sessions:** each visitor gets a cookie `prapti_sid` (48 hex characters). It is
  `HttpOnly; SameSite=Strict; Path=/`, and adds `Secure` unless the host is
  localhost or 127.0.0.1. Sessions live in a `Map` for at most 12 hours.
- **Client:** `localStorage` holds the tracker data (`prapti.tracker`), the helper
  mode data (`prapti.helper`) and the language choice (`prapti.lang`). Nothing
  personal is sent to the server.

## API

All API routes are stubs for now. Each returns JSON.

| Route                       | Behaviour                                        |
|-----------------------------|--------------------------------------------------|
| `GET /api/rules-check`      | `501 {"status":"not_implemented"}`               |
| `POST /api/editor/login`    | Body limit 16 KB (`413` if larger). Invalid JSON gives `400`. Otherwise `501`. |
| `/api/editor/*`             | Body limit applies. `501` stub.                  |
| other `/api/*`              | `404 {"error":"not_found"}`                      |

## Module contracts

- Each page module lives at `public/js/pages/<name>.js`.
- It exports `render(container, params)`:
  - `container` is the DOM element that the page fills. The module replaces its
    children and does not touch anything outside it.
  - `params` is an object of route parameters, for example `{ id: "..." }` for
    `/scheme/:id`.
  - It may return nothing, or a function that is called when the user leaves the page.
- Page modules do not fetch from the network. They use `t()` for all visible text.
- Each module is registered once in the route registry in `public/js/app.js`.

## Security headers

Every response carries a Content-Security-Policy, `X-Frame-Options: DENY`,
`X-Content-Type-Options: nosniff` and `Referrer-Policy: same-origin`. The CSP
allows scripts and styles only from `'self'` (styles may also come from
Google Fonts). Request bodies are capped at 16 KB.

## Scripts

- `npm start`: runs `server.js` (port from `PORT`, default 8080).
- `npm run build`: runs `build.js` and writes `dist/`.
- `npm test`: runs the `node:test` files in `tests/`.
